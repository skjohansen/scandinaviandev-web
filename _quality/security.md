## What security means: the CIA triad

Everything in security comes back to three properties, the CIA triad:

- **Confidentiality** — data is only accessible to those with the right to see it
- **Integrity** — data and system behaviour cannot be tampered with
- **Availability** — the system is there when people and other systems need it

Every control, policy and tool you deploy serves at least one of the three.
If you can say which one a requirement protects, you can reason about
security the way you reason about any other quality of the product.

## The goal of security is resilience

Security is not about locks and fear. The goal is resilience: software that
keeps working, even under attack. Security built in from day one instead of
bolted on before launch — threat modelling, secure code and security
automation in your pipeline, practised by the engineers you already have.

## Security in AI-supported development

AI-supported development changes how security is done, not why:

- **AI generates code fast — secure patterns make it safe by construction**, instead of catching what it produced afterwards
- **Automated security checks in the pipeline review AI output** at the same speed it is generated, giving humans time for judgement instead of triage
- **AI-assisted threat modelling** turns a workshop exercise into a routine part of design
- **Confidentiality applies to your AI tools too** — the data you feed them, and the access you give them, belongs in your security model

## Security as your ticket to the EU market

With the EU Cyber Resilience Act, solid security is more than hygiene — it
is your competitive edge to sell connected products across the entire EU
market. Compliance done well is a door-opener, not a burden.
