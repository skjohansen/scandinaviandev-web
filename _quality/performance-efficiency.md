## What performance efficiency means

Performance efficiency shows up in three characteristics:

- **Time behaviour** — response and processing times meet requirements
- **Resource utilisation** — the amounts and types of resources used are proportionate
- **Capacity** — the maximum limits of the product meet current and future requirements

## How performance efficiency improves security

The practices that keep software fast are the same ones that keep
vulnerabilities out:

- **Lean dependencies mean a smaller attack surface** — every unused dependency is code you maintain, patch and secure, but never benefit from
- **Tight feedback loops catch vulnerabilities early** — while they are cheap to fix, not after release
- **Capacity headroom is availability under attack** — software with margin keeps responding when load spikes, including the hostile kind

Every unused dependency is attack surface you maintain but never benefit
from. Performance efficiency is the discipline that removes it.

## Performance efficiency in AI-supported development

AI-supported development lives and dies by feedback speed. An assistant
that suggests a change needs to know, within seconds, whether it works:

- **Fast builds and tests make AI iteration viable** — a pipeline that takes an hour makes every AI suggestion an hour expensive
- **Quick feedback catches AI mistakes early** — generated code goes through the same automated security and quality gates as human code, at the same speed
- **Lean codebases give AI more useful context** — less code means less noise, and fewer confident mistakes
- **Automated security checks in the pipeline review AI output** without slowing your releases — no security rework late in the cycle

When your team spots risky patterns before code is written, there is no
security rework late in the release cycle — and releases stay fast.
